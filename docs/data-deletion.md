# 데이터 삭제와 운영 확인

이 안내는 배포본의 **앱이 관리하는 데이터**를 대상으로 합니다. 원본 저장소나 원본 Firebase의 데이터를 변경하지 않습니다.

## 업데이트 순서

참여자가 사용하지 않는 유지보수 시간에 자신의 Firebase 프로젝트로 아래 규칙을 배포하고 새 앱을 배포합니다.

```bash
firebase deploy --project YOUR_FIREBASE_PROJECT_ID --only firestore,storage
```

새 삭제 코드는 관리자 전용 하위 기록 삭제·Storage 목록/삭제 권한과 탈퇴 사용자 차단 규칙을 사용합니다. 이전 규칙만 남아 있으면 삭제가 권한 오류로 중단될 수 있습니다. 전체 허용 규칙으로 바꾸지 말고 저장소 규칙을 배포하세요. 현재 화면에 이미지가 없어도 저장소 확인을 위해 Storage 버킷과 규칙 설정이 필요합니다.

## 반 삭제

관리자의 반 관리 화면에서 삭제를 실행합니다. 먼저 반을 보관하여 참여자의 추가 쓰기를 막고 다음 데이터를 정리합니다.

- 반의 프로젝트, 활동과 응답, 활동 모둠과 낱말, 자료, 확인 기록, 도움 글
- 반의 공부방 보드와 카드
- 출석, 좌석 배치, 모둠 배정, 질문 신호
- 반과 연결된 참여 정보, 참여 코드·코드 조회·가입 요청, 메모, 기존 보상·KWL, 접속 상태와 방송
- 자신의 Storage에 있는 `book-project-images/<반 ID>/` 이미지

다른 반과 교사의 공용 수업 자료(`lessons`)는 반 삭제 대상이 아닙니다. 이전 코드로 다른 반에 내보낸 자료가 원래 반의 이미지 URL을 공유하고 있다면, 필요한 이미지를 대상 반의 경로에 복사한 뒤 원래 이미지를 삭제합니다. 외부 사이트의 이미지 URL이나 다른 버킷의 파일은 삭제하지 않습니다.

## 참여자 탈퇴

관리자 사용자 화면에서 대상 참여자를 선택해 탈퇴 처리합니다. 프로필, 참여 내역, 작성한 활동과 알려진 사용자 연결 기록을 정리하고, 좌석·모둠 등에 들어 있는 해당 사용자 참조를 제거합니다.

브라우저는 다른 사용자의 Firebase Authentication 계정이나 이미 발급된 인증 토큰을 직접 삭제할 수 없습니다. 따라서 `deletedUsers/<UID>`에 `{ deleted: true }`만 남겨 같은 UID로 앱 데이터가 재생성되는 것을 막습니다. 이름·학교·게시물 내용은 이 차단 기록에 넣지 않습니다. 운영자가 Firebase Console의 Authentication에서도 대상 UID를 확인해 계정을 삭제하세요. 차단 기록을 임의로 지우면 남아 있는 인증 세션의 재접근 방지가 해제될 수 있습니다.

이 기능은 현재 배포본의 관리자 1명·일반 참여자 구조를 대상으로 합니다. 유일한 관리자와 이전 앱의 교사 계정은 이 명령으로 삭제하지 않습니다. 이전 교사가 소유한 반·공용 수업 자료는 먼저 별도로 정리하거나 소유권을 이전해야 합니다.

## 실패와 재시도

삭제는 Firestore와 Storage 전체를 묶는 하나의 트랜잭션이 아닙니다. 네트워크·권한 오류가 생기면 일부 데이터만 삭제된 상태일 수 있습니다. 오류를 숨기지 않으며 부모 반 문서나 사용자 프로필을 마지막까지 유지해 다시 시도할 대상을 남깁니다.

- 창을 닫지 말고 완료 메시지를 기다리세요. 같은 관리자의 다른 탭에서도 해당 자료 편집을 멈추세요.
- 반 삭제 실패 후에는 보관된 반 목록에서 같은 반을 다시 삭제하세요. 실패한 반을 곧바로 보관 해제하지 마세요.
- 탈퇴 실패 후에는 같은 사용자를 다시 탈퇴 처리하세요. 차단 기록은 유지되므로 처리 중인 UID는 앱을 계속 사용할 수 없습니다.
- `permission-denied`이면 자신의 프로젝트 ID와 최신 규칙 배포 여부를 확인하세요.
- 이미지 복사 단계에서 CORS 오류가 발생하면 자신의 Storage 버킷에 앱 도메인의 GET 요청을 허용하세요. [Firebase의 직접 다운로드·CORS 설정 안내](https://firebase.google.com/docs/storage/web/download-files#cors_configuration)를 따르세요. 복사 실패 시 원래 이미지를 삭제하지 않습니다.

## 개별 항목과 공유 이미지

활동·자료에서 이미지 참조를 제거해도 같은 이미지를 다른 항목이 사용할 수 있으므로 Storage 파일을 즉시 삭제하지 않습니다. 이 파일은 반 전체 삭제 시 함께 정리합니다. 반·사용자 삭제와 개별 첨부 참조 제거를 구분하세요.

## 삭제 범위의 한계

이 코드는 저장소에 정의된 데이터 구조와 연결 정보를 기준으로 정리합니다. 과거 앱이 만든 출처 불명의 컬렉션이나 반 ID·부모 연결을 잃은 데이터까지 추측해 삭제하지 않습니다. 기존 DB를 가져왔다면 운영자가 이전 스키마와 내보내기 자료를 별도로 점검해야 합니다.

Firebase Authentication, Firestore 백업·PITR, Storage의 soft delete/객체 버전·보존 정책, 운영자가 만든 백업 파일은 별도로 관리합니다. 이미 다운로드한 파일, 브라우저 캐시, 스크린샷, 타인이 소유한 외부 URL은 회수할 수 없습니다. 반 보관은 삭제가 아니며, 기존 다운로드 토큰 URL을 자동 폐기하지 않습니다.

## 개발자 검증

```bash
npm --prefix tests/rules ci
npm run test:rules
npm --prefix tests/rules run test:storage
npm run test:distribution
npm run test:checklist
npm run build
```

삭제 테스트는 화면이 호출하는 공통 삭제 함수와 실제 Firestore 클라이언트 어댑터를 에뮬레이터에서 검증합니다. 실패·재시도, 다른 반 보존, 일반 참여자의 삭제 거부도 확인합니다. SDK의 테스트 종료 핸들은 Node의 강제 종료 옵션으로 닫되 테스트 자체의 타임아웃과 실패 결과는 유지합니다.
